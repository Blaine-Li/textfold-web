# TextFold 网页版

这个版本以浏览器作为入口，复用现有 Python 服务和阅读器，不需要 Electron 桌面应用。
当前交付包含**带个人登录的网页版**和外网部署配置，尚未执行部署。本机访问 `http://localhost:3017`。浏览器负责交互，Python 服务负责文件解析、模型调用和保存文档。账号初始化、固定域名与 HTTPS 配置见 [登录与外网访问说明](WEB-LOGIN.md)。

## 启动

首次准备（Python 3.9+；推荐 3.12）：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

此工作目录已经安装好运行依赖。以后在仓库根目录执行：

```sh
# 仅首次初始化账号（密码在终端输入）
./setup-account.sh init --username oursus
./start-web.sh
```

打开浏览器访问 `http://localhost:3017`，无需打开桌面 App。`PORT=3020 ./start-web.sh` 可以更换端口。启动器使用 `.web-data` 保存文档与笔记，使用 `.web-settings` 保存设置与密钥；两者和虚拟环境都已加入 Git 忽略。模型可以继续使用自动发现的本地服务，也可以从设置添加 API 供应商。

也可直接启动：

```sh
python3 -m textfold account init --username oursus
python3 -m textfold serve --web --auth --port 3017
```

直接启动沿用原有数据和设置目录，必须在同一设置目录初始化账号；可以通过 `TEXTFOLD_DATA` 和新增的 `TEXTFOLD_HOME` 分别指定目录。`--web` 会补充内置示例；仅设置 `TEXTFOLD_WEB=1` 开启网页能力限制，不自动添加示例。

## 已完成的取舍

| 功能 | 网页版本 |
| --- | --- |
| 五级缩放、卡片与导图、局部展开 | 保留原阅读器 |
| 链接、含文字的 PDF、Word、Markdown 等文件 | 沿用后端导入与解析 |
| 直接粘贴正文 | 新增，支持 Markdown、可选标题 |
| 无模型阅读 | 粘贴正文可保存并阅读原文；AI 折叠、翻译和问答需要可用模型 |
| 内置阅读指南 | 新增预先编写的五级示例，无需调用模型 |
| 文献库、文件夹、笔记、导出、原文对照 | 保留 |
| 已有本地模型发现与 API 供应商 | 保留，调用在服务端完成 |
| Zotero 本地库、ChatGPT 桥启动、自定义命令管理 | 网页模式隐藏入口，对应管理请求返回 403 |
| 迁移本地存储目录、安装/卸载大型 OCR 引擎 | 网页模式隐藏入口，对应管理请求返回 403 |
| 扫描件和图片识别 | 未安装引擎时提示改用含文字文档或粘贴正文；不在网页安装引擎 |

## 代码边界

- `textfold/server.py`：`capabilities()` 提供 `/api/capabilities`，并进入首页和模型数据。后端检查网页模式，避免仅隐藏按钮。
- `textfold/web/app.html`、`app.js`、`app.css`：浏览器首页、正文导入、能力驱动的精简设置；复用原来的阅读组件、配色和字体。
- `textfold/web_demo.py`：幂等生成示例文档；原文明确说明示例预先编写，不冒充实时模型生成。
- `textfold/__main__.py`：`serve --web` 入口。默认 `serve` 和桌面版保持兼容。
- `textfold/store.py`：支持 `TEXTFOLD_HOME`，隔离实例设置，不把 API 密钥放入代码。

前端沿用原有浅/深背景、紫色重点色 `#6B5CE7`、橙色品牌标记、Inter 控件字体与 Source Serif 阅读字体。新增内容围绕导入与阅读排列，不另建产品展示页；窄屏时操作与示例入口自动换行。

## 远程网页部署

个人账号登录、固定域名白名单、HTTPS Cookie 与反向代理配置已实现，详见 [登录与外网访问说明](WEB-LOGIN.md)。下面列出未来多人版的扩展方向。本次没有进行实际部署。

若希望手机或其他电脑通过域名访问，需要继续做服务器部署。默认仍只监听 `127.0.0.1`；公开地址必须显式设置，认证启用后写入请求需通过精确的同源校验。

建议顺序：

1. 把模型统一为服务端配置的 API 供应商，明确个人版或多人版的数据边界。
2. 在现有个人登录基础上增加多用户与文档权限，按用户隔离文件、笔记、任务与模型配置。
3. 在有身份认证的反向代理后部署 Python 服务，配置 HTTPS、明确的域名白名单、上传限制与并发任务队列。
4. 再决定是否需要对象存储、任务恢复、扫描识别和跨设备同步。

无需为了远程部署重写成熟的五级阅读器。可先发布单用户版本，再按实际需要增加多人能力。
